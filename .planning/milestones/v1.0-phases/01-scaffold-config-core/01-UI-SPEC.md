# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Phase 1 scope:** A bootable static app shell — dark dashboard header + placeholder content area. No grid, no rendered widgets, no theme system (Phases 2/3). The contract below covers ONLY the shell; tokens are declared now so Phase 3's theme system reuses them without migration.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — CSS Modules + CSS custom properties (locked by STACK.md; shadcn/ui and component libraries explicitly rejected for kiosk chrome) |
| Preset | not applicable |
| Component library | none — custom primitives only (introduced in later phases) |
| Icon library | none in this phase — lucide-react is in the stack but Phase 1 has zero interactive elements (decorative empty-state icon optional, not required) |
| Font | Inter Variable — self-hosted via `@fontsource-variable/inter` 5.3.x (no Google Fonts network dependency; offline-resilient) |

### Phase 1 Shell Contract

Two surfaces only — no other UI in this phase:

| Surface | Spec | Token bindings |
|---------|------|----------------|
| **Header bar** | Fixed height `48px` (`2xl` = 48px), full-width, `--surface` background, `1px` hairline bottom border `--border`; contains the "DeskMate" wordmark (20px / 600 / 1.2, `--text-primary`) left-aligned at `16px` padding. No buttons, no actions. | `--surface`, `--border`, `--text-primary` |
| **Placeholder area** | Remaining viewport height, centered empty state: a card on `--surface-raised` with `1px` `--border` hairline, `8px` radius, `24px` internal padding; heading + body copy per Copywriting Contract. No grid, no skeleton, no shimmer (nothing to load — grid is Phase 2). | `--surface-raised`, `--border`, `--text-primary`, `--text-muted` |

CSS custom properties are declared on `:root` in the global stylesheet as the single source of truth (ThemeProvider is Phase 3; Phase 1 just declares the dark token set).

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Compact element spacing, card radius |
| md | 16px | Default element spacing, header content padding |
| lg | 24px | Section padding, placeholder card internal padding |
| xl | 32px | Layout gaps between header and content |
| 2xl | 48px | Header bar height, major section breaks |
| 3xl | 64px | Page-level spacing |

Exceptions: none. (Icon-only touch targets at 44px+ are a later-phase concern — no icons in this phase.)

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 (regular) | 1.5 |
| Label | 14px | 400 (regular) | 1.5 |
| Heading | 20px | 600 (semibold) | 1.2 |
| Display | 28px | 600 (semibold) | 1.2 |

Declared weights: **400 (regular)** and **600 (semibold)** only. Inter Variable may render intermediate weights — do not use them.

Usage in Phase 1: wordmark + placeholder heading use **Heading (20px/600)**; placeholder body uses **Body (16px/400)**; future small meta/eyebrow text uses **Label (14px/400)**. Display (28px) is declared now for the Phase 3 clock widget and is not used in this phase.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0A0D12` | Page/shell background — the near-black surface the dashboard sits on |
| Secondary (30%) | `#141A22` | Header bar background, placeholder card surface (`--surface`, `--surface-raised`) |
| Accent (10%) | `#22D3EE` | See reserved list below |
| Destructive | `#F87171` | Declared for future phases only — **not used in Phase 1** (no destructive actions exist) |
| Text primary | `#E6EAF0` | Wordmark, headings, body copy |
| Text muted | `#8A93A0` | Placeholder body hint, secondary text |
| Border (hairline) | `#232B36` | Header bottom hairline, card outlines |

Token mapping (CSS custom properties on `:root`):

```
--background:    #0A0D12   (60% dominant)
--surface:       #141A22   (30% secondary)
--surface-raised:#141A22   (30% secondary — same value in v1, separate token so Phase 3 themes can differ)
--accent:        #22D3EE   (10%)
--destructive:   #F87171   (unused in Phase 1)
--text-primary:  #E6EAF0
--text-muted:    #8A93A0
--border:        #232B36
```

**Accent reserved for** (explicit list — never "all interactive elements", and nothing in Phase 1 is interactive):
1. `:focus-visible` ring on any future interactive element (2px ring, 2px offset — accessibility, not decoration)
2. Wordmark accent — a single accent glyph in "DeskMate" (e.g., the "D" or a trailing dot) if the executor wants a brand touch; optional
3. Placeholder-area eyebrow accent (small 14px label above the placeholder heading) — optional
4. Seeding Phase 3's theme accent token (declared here, consumed there)

The `--destructive` token exists so Phase 2+ confirmation UIs have a pre-declared value; it must not appear in the Phase 1 shell.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | **N/A — Phase 1 has no user actions.** The shell renders a static header + placeholder. The first CTA ("Add Widget") is introduced in Phase 2. |
| Empty state heading | **"Your dashboard is ready"** (Heading 20px/600, `--text-primary`) |
| Empty state body | **"Widgets will render here — grid editing arrives in the next update."** (Body 16px/400, `--text-muted`) |
| Error state | **N/A per D-07 — recovery is silent, no UI.** When stored config is corrupt/invalid/version-mismatched, the app falls back to defaults and logs only a console warning. Console warning format (the only "error surface" this phase): `[deskmate:storage] config rejected (version=…): <reason> — raw backup preserved at deskmate.config.backup` |
| Destructive confirmation | **None in this phase.** No destructive actions exist; nothing can delete, reset, or overwrite user data through the UI. (Backup overwrite of the raw-bad-data key is a data-layer concern, not a UI action — covered by D-06/D-08.) |

Copy tone: calm, zero-config, offline-friendly. No marketing voice — the shell is a kiosk surface, not a landing page.
