Storage contract (Pitfall 6 + D-06/D-08/D-11):
```typescript
export const STORAGE_KEY = 'deskmate.config.v1';   // versioned (D-11)
export const BACKUP_KEY  = 'deskmate.config.backup'; // raw bad data (D-06)
export function storageAvailable(): boolean;        // probe setItem/removeItem, catch quota-0/private-mode
export function loadConfig(): DashboardConfig | null; // raw→parse→validate→(migrate)→defaults; never throws
export function saveConfig(config: DashboardConfig): void; // only ever called with a validated object

```

On-disk wire format (wrapper-level persist storage, Task 3): the key `deskmate.config.v1` ALWAYS contains the RAW `DashboardConfig` JSON — never the zustand persist `{ state, version }` envelope. The persist wrapper's `setItem` strips the envelope and stores only `state.config`; its `getItem` parse-guards the raw string (parse failure → `backupRaw(raw)` + console.warn + return null → defaults hydrate) and validates before returning a rehydrate string. This makes the on-disk format identical to what Phase 2's `loadConfig()` reads — one format, one validator, all three transports.

Console warning format (UI-SPEC — the only error surface, D-07):
`[deskmate:storage] config rejected (version=…): <reason> — raw backup preserved at deskmate.config.backup`

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| localStorage → store | Untrusted stored data (corrupt JSON, hand-edited, browser-sync residue, future-version) crosses into the app — MUST be validated before any render or write |
| config object → zustand state | Raw parsed JSON must never reach React state unvalidated (prototype pollution / XSS vectors) |
| store → localStorage | Only validated config may be written back (validated-in, unvalidated-out is forbidden) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-10 | Tampering | storage.ts loadConfig (JSON.parse of stored value) | mitigate | Every read path: try/catch JSON.parse + `validateConfig` (zod safeParse) before anything renders (Task 2/3); never render or spread unvalidated data; adapter-only storage access (grep gate `localStorage` outside src/config/storage.ts → 0) |
| T-01-11 | Tampering | prototype pollution via `__proto__`/`constructor` keys in stored JSON | mitigate | zod unknown-key strip (no `.passthrough()`); parsed output is the only object ever spread into store state (merge validates first); Test 5 in schemas.test.ts + recovery tests assert no `__proto__` key survives |
| T-01-12 | XSS | executable payloads smuggled via stored/imported config | mitigate | v1 schema has no code-bearing fields (settings is a data record; widget code is Phase 4 and ONLY ever goes to a sandboxed srcdoc iframe); app never uses dangerouslySetInnerHTML (grep gate → 0); schema caps widgets at 50 (D-03) |
| T-01-13 | Tampering | backup overwrite destroying the raw bad data | mitigate | `backupRaw` writes-if-different (compares current backup content); backup is written BEFORE any main-key overwrite; getItem/setItem methods only (never property access) |
| T-01-14 | Tampering | unvalidated config written back to storage | mitigate | `saveConfig` only accepts the validated type; store merge validates before commit; persist serializes store state, which is always the validated object |
| T-01-SC | Tampering | npm/pip/cargo installs | accept | No package installs in this plan — all Phase 1 installs were gated by the blocking-human checkpoint in plan 01-01 (T-01-01/T-01-SC there) |
