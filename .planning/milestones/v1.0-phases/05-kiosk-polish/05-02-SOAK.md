# Phase 5 Plan 02: On-Hardware Soak Procedure

**Prepared:** 2026-08-16
**Status:** READY — to be executed on real hardware (phone / idle monitor) per the Phase 5 success criterion 5 + STATE.md verify flags.

> This procedure cannot be executed in the dev environment. It is the checklist the app owner runs on-device after deploying. The app already ships the instrumentation (kiosk diagnostics panel) the procedure reads.

## Preconditions

- Deploy the app to an HTTPS host (wake lock + PWA require a secure context; localhost also works for testing).
- Install as PWA: open the deployed URL → browser install affordance → "DeskMate" launches standalone fullscreen.
- Confirm the shared-config URL (`?config=…`) loads the exact configuration on the target device (Core Value check).

## 1. 24-Hour Kiosk Run

| Step | Action | Pass criteria |
|------|--------|---------------|
| 1.1 | Launch DeskMate fullscreen on the target device (phone or monitor) | App fills the screen; header shows "Screen awake" chip when supported |
| 1.2 | Open the diagnostics panel (gauge icon) | Panel shows live fps/heap/wake-lock/visibility |
| 1.3 | Run continuously for **24 h** | No crash, no blank screen, no unresponsive state |
| 1.4 | Sample diagnostics **hourly** (record into the log table below) | fps stays ≥ 30 (typical idle kiosk 60); heap growth < 20% over the run; wake lock remains active where supported |
| 1.5 | Hide the tab briefly (minimize) then return | Wake lock re-acquires (chip returns to "Screen awake" within seconds) — KIOSK-02 |
| 1.6 | Rotate/resize the device at least twice | Grid ↔ single-widget view switches without glitches (GRID-05) |
